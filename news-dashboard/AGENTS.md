# Agent 工作守则

本文件用于约束后续 Agent 在本项目中的行为，降低上下文消耗、避免误改核心逻辑。

## 修改前必读

- 任何代码修改前，**必须先读取** `PROJECT_CONTEXT.md` 和 `ARCHITECTURE.md`
- 两份文档合计约 8KB，可在 1 分钟内建立项目定位与模块认知
- 阅读后按文档中的「推荐读取顺序」定位目标文件，不要从头扫描整个项目

## 禁止默认全项目扫描

- 禁止在每次任务开始时 `cat` / 遍历全部 `.py` / `.json` / 前端文件
- 禁止读取 `data/*.json` 的大文件（单文件可达 700KB）作为例行操作
- 小任务只读取与目标功能相关的 1-3 个文件

## 小任务读取范围

| 任务类型 | 只读文件 |
|---|---|
| 改分类/评分 | `rules.py` + `fetcher.py` 相关函数 |
| 改翻译 | `translation_service.py` |
| 改热点 | `game_hotspot.py` |
| 改 API | `app.py` |
| 改前端 | `static/script.js` + `templates/index.html` |
| 改数据源 | `github_fetcher.py` 或 `config.py` |

## 修改前明确范围

- 动手前先说明：目标文件、改动函数、影响的数据文件、涉及的前端/API
- 如影响多个模块，先说明模块间调用链再修改

## 优先使用已有索引

- 先查 `ARCHITECTURE.md` 的关键函数入口表和模块调用关系
- 有 `graphify-out/` 知识图谱时，优先用 `/graphify query` 定位
- 不要通过搜索整个目录猜测代码位置

## 禁止未经允许重构 pipeline

- `fetcher.py` 的采集 → 分类 → 评分 → 翻译 → 热点主链路属于核心 pipeline
- 未经用户明确授权，禁止重构、重排、合并或拆分这些步骤
- 新功能应增量接入，不改变既有流程

## 需要扩大读取范围时先说明

- 如果现有索引不足以定位问题，需读取额外文件时，先说明：
  - 为什么现有文档不够
  - 准备读取哪些文件
  - 预计影响范围
- 获得确认后再扩大读取
